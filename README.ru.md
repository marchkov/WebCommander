# WebCommander

### Клавиатурная навигация

В активной файловой панели **↑/↓** перемещают курсор в порядке видимых строк,
включая `..`. **Enter** открывает текущую папку или редактирует файл;
**Backspace** переходит в родительскую папку. У `/` и корней дисков строки `..`
нет. **F3** открывает файл только для чтения, **F4** — для редактирования.
При просмотре кнопка Save скрыта, запись через Ctrl/Cmd+S запрещена.
Ctrl/Cmd-клик сохраняет множественное выделение; стрелки возвращают одиночное.
Терминал и текстовые поля сохраняют обычную обработку клавиш.

### Терминалы панелей

Кнопка **>_** в заголовке каждой панели открывает терминал под её списком файлов.
Левый и правый терминалы независимы. Локальная панель запускает локальный PTY,
SSH-панель использует своё существующее SSH-соединение. Shell стартует в текущем
каталоге панели. Последующая навигация по файлам не меняет каталог работающего shell.
Закрытие и повторное открытие либо **Reconnect** запускает новый shell в актуальном
каталоге панели. После выхода история остаётся видимой. Смена провайдера или
SSH-сессии закрывает терминал; после разрыва SSH сначала подключите панель заново.
Горячие клавиши файлового менеджера продолжают работать вне фокуса терминала.

Тесты клиентского протокола: `node --test tests/terminal.test.cjs`.
Прокси Vite `/api` передаёт обычные HTTP-запросы и WebSocket-upgrade.

#### Backend терминалов

WebSocket `/api/terminal` работает на том же HTTP-сервере и использует cookie
существующей Express-сессии. При включённой авторизации требуется вход.
Origin браузера должен соответствовать Host; reverse proxy должен сохранять
Host и передавать WebSocket-upgrade. Один сокет открывает один shell.
Первое сообщение — JSON:

```json
{"type":"open","provider":"local","cwd":"D:/data","cols":120,"rows":30}
```

Для SSH укажите `"provider":"sftp"`, существующий `sessionId` этой веб-сессии и
абсолютный POSIX-путь `cwd`. Логин, пароль и ключи здесь не принимаются.
Дальше доступны `{"type":"input","data":"pwd\r"}`,
`{"type":"resize","cols":120,"rows":30}` и `{"type":"close"}`.
Допустимы 10–500 столбцов и 2–200 строк. Ответы: `ready`, `output` (UTF-8 `data`),
`error` (`message`), `exit` (`code`, `signal`). `ready` означает готовность канала
принимать ввод; для SSH начальная экранированная команда `cd` поставлена в очередь.
Лимит сообщения — 64 КиБ. Закрытие сокета, выход shell и остановка сервера очищают
ресурсы; heartbeat обнаруживает потерянные соединения.

Локальный shell использует node-pty: PowerShell на Windows, `$SHELL`/bash/sh на
Unix. LocalProvider проверяет стартовый каталог, включая ссылки. Это **не изоляция
файловой системы**: команды выполняются с правами серверного пользователя.
SSH использует PTY-канал существующего соединения. `/api/ssh/exec` сохранён.
Windows-адаптер содержит локальный обход ошибки очистки ConPTY в node-pty 1.1;
его следует перепроверить при обновлении зависимости.

Для сборки node-pty на Linux нужны Python, make и C++-компилятор; Dockerfile
устанавливает их. Основные тесты используют имитацию PTY. Проверка настоящего
терминала в PowerShell:

```powershell
$env:WC_TEST_REAL_PTY = '1'
node --test server/services/terminalPty.integration.test.js
Remove-Item Env:WC_TEST_REAL_PTY
```

### ZIP-архивы

Выберите файлы или папки и нажмите **Pack to ZIP**. Предлагаемое имя —
`archive.zip`, а для одной папки — `<имя папки>.zip`. В архиве сохраняются имена
выбранных элементов, вложенные и пустые папки, бинарные данные.
Для выбранных `.zip` используйте **Extract here**: распаковка идёт в текущую папку.
Обе операции поддерживают локальные и SFTP-панели через потоки на сервере.

Создание не перезаписывает существующий архив. Распаковка по умолчанию сообщает
о конфликте; после подтверждения файлы можно заменить. Замена файла папкой или
папки файлом запрещена. Сама папка назначения может уже существовать.
После ошибки ранее распакованные файлы могут остаться; панель обновится.
Запрещены создание архива внутри выбранной папки, одинаковые имена элементов,
циклические ссылки, опасные пути ZIP и ссылки за пределы папки распаковки.

API: `POST /api/archives/create` принимает `{ provider, sessionId?, sources, destination }`;
`POST /api/archives/extract` — `{ provider, sessionId?, archive, destination, overwrite? }`.
Провайдер: `local` или `sftp`; для SFTP нужен `sessionId`. По умолчанию `overwrite=false`.

Проверка backend: `node --test server/*.test.js server/providers/*.test.js server/services/*.test.js`.

Двухпанельный файловый менеджер с веб-интерфейсом и серверной частью для работы с реальными файлами.

## 🛠️ Установка

1. Клонируйте репозиторий или скачайте исходный код:
```bash
git clone <repository-url>
cd webcommander
```

2. Установите зависимости:
```bash
npm install
```

3. Настройте конфигурацию в файле `config.json`:
```json
{
  "port": 3001,
  "rootPath": "/srv/webcommander/files",
  "auth": {
    "enabled": true,
    "users": [
      {
        "username": "admin",
        "password": "<set-your-password>"
      }
    ],
    "sessionSecret": "<set-random-session-secret>",
    "sessionMaxAge": 86400000
  },
  "security": {
    "allowedPaths": ["/srv/webcommander/files"],
    "blockedPaths": ["/etc", "/root", "/var/log"],
    "maxFileSize": 104857600,
    "allowedExtensions": ["*"]
  }
}
```

## ⚙️ Конфигурация

### Основные параметры

- `port` - порт сервера (по умолчанию 3001)
- `rootPath` - корневая директория для файлового менеджера

### Аутентификация

- `auth.enabled` - включить/выключить систему входа (true/false)
- `auth.users` - массив пользователей с логином и паролем
- `auth.sessionSecret` - секретный ключ для сессий (ОБЯЗАТЕЛЬНО измените в production!)
- `auth.sessionMaxAge` - время жизни сессии в миллисекундах (по умолчанию 24 часа)

### Безопасность

- `security.allowedPaths` - массив разрешенных директорий (пользователь может работать только внутри них)
- `security.blockedPaths` - массив заблокированных директорий (даже если они внутри allowedPaths)
- `security.maxFileSize` - максимальный размер загружаемого файла в байтах (по умолчанию 100MB)
- `security.allowedExtensions` - разрешенные расширения файлов (["*"] для всех)

## 🚀 Запуск

### Режим разработки

```bash
# Терминал 1: Запуск сервера
node server/index.js

# Терминал 2: Запуск фронтенда
npm run dev
```

Откройте http://localhost:3000 в браузере

### Production режим

1. Соберите фронтенд:
```bash
npm run build
```

2. Запустите сервер:
```bash
NODE_ENV=production node server/index.js
```

Сервер будет обслуживать статические файлы из папки `dist` и API на порту 3001

### Docker

Проект поддерживает запуск в контейнере. Для Docker используются переменные окружения:

- `WC_PORT` — порт приложения
- `WC_ROOT_PATH` — корневая папка, доступная для управления файлами
- `WC_ALLOWED_PATHS` — список разрешённых директорий через запятую
- `WC_BLOCKED_PATHS` — список запретных директорий через запятую
- `WC_AUTH_ENABLED` — включить/выключить авторизацию
- `WC_AUTH_USERS` — JSON-строка массива пользователей
- `WC_SESSION_SECRET` — секрет для сессий
- `WC_SESSION_MAX_AGE` — время жизни сессии в миллисекундах
- `WC_MAX_FILE_SIZE` — максимальный размер файла
- `WC_ALLOWED_EXTENSIONS` — разрешённые расширения через запятую

Пример `.env`:

```env
WC_PORT=3001
WC_ROOT_PATH=/data/webcommander
WC_ALLOWED_PATHS=/data/webcommander
WC_BLOCKED_PATHS=/etc,/root,/var/log
WC_AUTH_ENABLED=true
WC_AUTH_USERS=[{"username":"admin","password":"***REMOVED***"}]
WC_SESSION_SECRET=<set-random-session-secret>
WC_SESSION_MAX_AGE=86400000
WC_MAX_FILE_SIZE=104857600
WC_ALLOWED_EXTENSIONS=*
```

Запуск через Docker Compose:

```bash
docker compose up --build
```

Для запуска без Compose можно собрать образ вручную:

```bash
docker build -t webcommander .
docker run -p 3001:3001 -v "${PWD}/data:/data/webcommander" -e WC_ROOT_PATH=/data/webcommander -e WC_ALLOWED_PATHS=/data/webcommander --name webcommander webcommander
```

## 🔐 Безопасность

### Важные рекомендации:

1. **Измените sessionSecret** в config.json на случайную строку
2. **Измените пароли** пользователей, особенно если используются демонстрационные значения
3. **Настройте allowedPaths** - ограничьте доступ только нужными директориями
4. **Используйте HTTPS** в production (настройте reverse proxy с SSL)
5. **Запускайте от непривилегированного пользователя** (не root)

### Пример настройки Nginx reverse proxy:

```nginx
server {
    listen 443 ssl http2;
    server_name files.yourdomain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://localhost:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        
        # Для загрузки больших файлов
        client_max_body_size 100M;
    }
}
```

## 🔌 SSH Подключения

WebCommander поддерживает работу с удалёнными серверами через SSH. Вы можете переключить любую панель в SSH-режим для работы с файлами на удалённом сервере.

### Подключение к SSH

1. Нажмите кнопку **"L: Local"** или **"R: Local"** в панели инструментов (в зависимости от того, какую панель хотите переключить)
2. Заполните форму подключения:
   - **Host** - IP-адрес или домен сервера
   - **Port** - порт SSH (по умолчанию 22)
   - **Username** - имя пользователя
   - **Authentication** - пароль или SSH-ключ
3. Нажмите **Connect**

### Возможности SSH-режима

- 📁 Навигация по файловой системе удалённого сервера
- 📝 Просмотр и редактирование текстовых файлов
- 📋 Копирование файлов с SSH на локальный сервер (через скачивание)
- 🗑️ Удаление файлов и папок
- 📂 Создание директорий
- 🔄 Переключение между локальным и SSH-режимом в любой момент

### Особенности

- SSH-сессии хранятся на сервере и автоматически закрываются при переключении панели обратно в локальный режим
- Поддерживается аутентификация по паролю и SSH-ключу (RSA, DSA, ECDSA, Ed25519)
- Для SSH-ключей с паролем можно указать passphrase
- Индикатор режима отображается в заголовке панели (зелёный бейдж "SSH")

### Примеры использования

- **Редактирование конфигов на сервере** - подключитесь к серверу и редактируйте файлы напрямую
- **Скачивание логов** - переключите панель в SSH, скачайте логи на локальный сервер
- **Управление файлами** - создавайте папки, удаляйте файлы на удалённых серверах
- **Сравнение файлов** - откройте один файл локально, другой через SSH для сравнения

## 📱 Использование

### Вход в систему

1. Откройте веб-интерфейс в браузере
2. Введите логин и пароль (по умолчанию: admin / ***REMOVED***)
3. После успешной авторизации откроется файловый менеджер

### Основные операции

- **Навигация** - двойной клик по папке для входа, кнопка ".." для возврата
- **Выбор файлов** - клик для выбора, Ctrl+клик для множественного выбора
- **Копирование (F5)** - копирует выбранные файлы в другую панель
- **Перемещение (F6)** - перемещает выбранные файлы в другую панель
- **Создание папки (F7)** - создает новую папку в текущей директории
- **Удаление (F8)** - удаляет выбранные файлы/папки
- **Редактирование** - двойной клик по текстовому файлу открывает редактор
- **Скачивание** - используйте кнопку загрузки в панели инструментов

### Горячие клавиши

- `Tab` - переключение между панелями
- `F5` - копировать
- `F6` - переместить
- `F7` - создать папку
- `F8` - удалить
- `Ctrl+R` - обновить
- `Ctrl+S` - сохранить файл (в редакторе)
- `Esc` - закрыть редактор

## 🐛 Решение проблем

### Ошибка "Cannot find module"
```bash
npm install
```

### Порт уже занят
Измените `port` в config.json

### Нет доступа к файлам
Проверьте:
- Права доступа пользователя, от которого запущен сервер
- Настройки `allowedPaths` и `blockedPaths` в config.json

### Не работает аутентификация
- Проверьте, что `auth.enabled` установлен в `true`
- Убедитесь, что пользователь существует в массиве `auth.users`

### Восстановление SSH и сочетания клавиш

SSH-соединения хранятся в памяти сервера и переживают перезагрузку страницы и навигацию фронтенда, пока работают серверный процесс и SSH-соединение. Перезапуск сервера, перезагрузка ОС или авария процесса завершают их. Keepalive выполняется каждые 10 секунд, допускается до трёх проверок без ответа.

**Connections (Ctrl+F)** показывает соединения текущей веб-сессии. Можно подключить существующее соединение к активной панели, отключить его или открыть форму нового подключения. Переключение панели в Local только отсоединяет панель. Disconnect в Connections возвращает в Local обе панели, если они использовали это соединение.

В `sessionStorage` сохраняются только режим панели, идентификатор SSH-сессии и текущий путь — без паролей, ключей и passphrase. После перезагрузки каждая панель восстанавливается независимо. Если сохранённый путь недоступен, используется домашний каталог `~` или локальный корень `/`. Для потерянного соединения необходимо заново ввести данные входа. Соединения другой веб-сессии недоступны.

Insert переключает выделение текущей строки и перемещает курсор дальше; Ctrl+A / Num+ выделяют все реальные элементы; Num* инвертирует выделение; Num− снимает выделение. Маски пока не поддерживаются. Ctrl+R обновляет панель, Ctrl+U меняет панели местами. Терминал и текстовые поля сохраняют собственные сочетания. На экране входа работают стандартные Tab/Shift+Tab и отправка формы через Enter; начальный фокус — Username.

Alt+F5 упаковывает выделенные элементы в ZIP, Alt+F9 распаковывает выделенные ZIP-файлы. Shift+F4 создаёт пустой текстовый файл без перезаписи существующего и открывает редактор. Shift+F6 переименовывает текущий элемент (или единственный выделенный) внутри его каталога. Alt+Enter показывает свойства без редактирования. Ctrl+T переключает терминал активной панели; при фокусе в самом терминале сочетание остаётся у терминала. Действия поддерживают Local и SSH и не перехватывают ввод в редакторе, модальных окнах и текстовых полях.

При переименовании существующий файл, каталог или символическая ссылка назначения вызывают HTTP 409 (`DESTINATION_EXISTS`). Переименование в тот же путь ничего не меняет. Local и SFTP проверяют назначение через `lstat` перед операцией. Проверка не даёт атомарной гарантии: Node не предоставляет переносимого rename без замены для файлов и каталогов, а поведение SFTP зависит от сервера. Внешний процесс может создать назначение между проверкой и переименованием. Настройки перезаписи Move/Transfer остаются отдельными.
